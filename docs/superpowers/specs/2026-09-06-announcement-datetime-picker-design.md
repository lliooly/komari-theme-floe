# 公告日期时间选择器

## 已确认范围

公告管理表单的开始时间和结束时间从浏览器原生 `datetime-local` 输入替换为自定义日期时间选择器。用户点击时间字段后打开同一个弹层，在弹层内选择日期、小时、分钟和时区；分钟粒度为 1 分钟，不再要求用户手写完整时间字符串。

开始时间和结束时间共用一个临时时区选择。时区初始为用户系统的 IANA 时区，例如 `Asia/Shanghai`；用户可以在当前编辑过程中切换时区，但时区选择不写入公告配置。下次打开编辑器时重新使用系统时区。

公告访客端、公告显示条件、公告内容、文字颜色、保存按钮和立即关闭逻辑不变。现有 `startsAt`、`endsAt` ISO 字符串格式保持兼容，不增加主题配置字段。

## 选择器组件

新增通用的 `DateTimePicker` 组件，使用项目已有的 Radix Popover，不引入第三方日期库。

- 触发器是一个真正的 `button`，以输入框样式显示当前日期时间或空值占位文案。
- 弹层顶部显示当前查看月份，提供上月和下月按钮。
- 弹层主体显示按周排列的日期网格，当前日期和已选日期有明确视觉状态。
- 弹层底部提供小时下拉框 `00–23`、分钟下拉框 `00–59`、时区下拉框和清除按钮。
- 值为空时，弹层默认查看今天；选择日期后默认补齐 `00:00`，用户可以继续调整时分。
- 开始和结束选择器绑定不同的日期时间值，但绑定同一个临时时区状态；任一弹层内切换时区，另一字段下次打开时也使用该时区。

月份标题、星期标题和触发器显示值使用当前界面语言格式化。时区选项使用浏览器支持的 IANA 时区列表，并确保当前系统时区和 `UTC` 始终存在；无法读取系统时区时回退到 `UTC`。

## 时间与时区数据流

`AnnouncementEditor` 保留 `start` 和 `end` 的本地日期时间字符串状态，新增只存在于编辑器生命周期内的 `timezone` 状态。选择器负责产生 `YYYY-MM-DDTHH:mm` 形式的本地墙上时间，不直接负责公告保存。

打开已有公告时，现有带时区 ISO 时间先按当前系统时区转换为选择器的本地值。因为时区不持久化，选择器重新打开时以当前系统时区为准。

保存时，表单使用用户当前选择的 IANA 时区将开始和结束本地时间转换成绝对时间，再调用现有的 `toISOString()` 兼容格式写入 `startsAt` 和 `endsAt`。切换时区会保留日期与时分文本，因此用户选择的本地时刻不变，但对应的绝对时刻会按新时区重新计算。

时间转换使用浏览器 `Intl.DateTimeFormat` 能力计算指定时区的偏移，并验证转换后的日期、时分是否与用户选择完全一致。夏令时跳过的不存在时间视为无效；重复时间采用浏览器可确定的一个有效实例。无法解析的时区或日期返回无效，不会发布公告。

## 校验与兼容性

保留现有发布校验：公告启用时内容不能为空，开始和结束必须是有效时间，结束必须晚于开始且晚于当前时间。选择器清除或未选择完整的字段最终转换为无效时间，并继续使用现有公告校验提示。

日期计算以日期字段为准，避免直接用 UTC 时间戳生成月历时产生跨日偏移。选择器只在客户端交互中使用浏览器 API；初始渲染使用稳定的空值/系统默认回退，避免 SSR 与 hydration 不一致。

不改变旧配置解析，不要求旧公告增加时区字段；旧配置缺少任何新 UI 状态时仍可正常显示和编辑。保存失败时保留用户当前选择，不更新已发布公告。

## 可访问性与文案

触发器、月历导航按钮、日期按钮、时分下拉框、时区选择器和清除按钮都可通过键盘操作。日期按钮使用选中状态和可读标签，弹层关闭后焦点回到对应触发器；按钮与选择器保留至少 40px 的操作区域。

为以下新增或调整的界面文案补充 `en`、`zh-CN` 和 `zh-TW` 翻译：选择日期时间、选择时区、小时、分钟、清除、上个月、下个月、今天，以及空值占位文案。月份和星期名称由 `Intl` 根据当前语言生成，不硬编码语言文本。

## 验证

- 运行 `npx tsc --noEmit` 和 `npm run build`。
- 验证空值、已有值回显、选日期、切换月份、选择小时/分钟、清除和保存。
- 验证开始/结束共用时区，切换时区后仍保留本地日期与时分，重新打开时回到系统时区。
- 验证浅色/深色主题、中英文/繁体中文、桌面/移动宽度和键盘焦点。
- 验证结束早于开始、已过期、无效日期、夏令时不存在时间和保存失败。
- 执行 `git diff --check`，确认只修改选择器、公告编辑器、时间工具、翻译和规格/计划文档。

## 不在本次范围

不把时区写入 `Announcement` 或主题配置，不改变访客端显示时区，不新增时间格式偏好，不增加重复日期库依赖，不重做公告编辑器的 Markdown、颜色或发布流程。
