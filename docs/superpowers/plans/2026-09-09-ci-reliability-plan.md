# CI 可靠性与 Dependabot 自动合并实施计划

用户已于 2026-09-09 要求实现自动合并设计，并落实 CI 审查中的修复和优化。

1. 新增不 checkout PR 代码的 `pull_request_target` 工作流，只处理可信 Dependabot patch/minor，保留人工拒绝意见，检查当前提交和必需检查配置，幂等审批及启用自动合并。
2. 翻译同步使用 Node 内置能力；严格解析全部输入，禁止 dry-run 请求网络，限制请求超时和重试，校验插值占位符，全部翻译成功后才写文件。使用源快照识别已存在文案的更新。
3. 翻译仅在 main 的相关文件变更或手动触发时运行。先计算差异，仅有修改时安装依赖并执行完整验证，然后创建翻译 PR，显式触发该分支构建。
4. 构建维持单个质量检查 job，统一 Node 22，固定 Actions SHA，增加任务超时、工作流校验及翻译校验；PR 产物保留 3 天，其他产物 7 天，避免压缩 ZIP 两次。
5. 发布只创建新版本，完整的已有发布不重写；先创建 draft、上传完成后发布，根据稳定版本顺序决定 latest。串行化发布，禁止取消进行中的发布。
6. Dependabot 保留两个生态、周更和每生态 5 个 PR 上限，对 patch/minor 分组，major 独立。缓存优化以减少空转为先，不增加跨运行产物复用。
7. 用模拟 GitHub CLI 和翻译请求覆盖安全边界与失败分支，运行 actionlint、npm test、lint、完整构建和打包检查。
8. 验证后配置远端 required `build`（GitHub Actions app 15368）、允许 Auto-merge 和 Actions 审批，保留已有规则。此项由用户“落实所有 CI 建议”的扩展范围授权，超出原自动合并文档的文件变更范围。

不创建 worktree 或额外开发分支，不使用视觉伴侣。不创建测试用远端 PR、不调用付费翻译接口、不重新发布已有版本。
